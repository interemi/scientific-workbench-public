# Synthetic first-run examples

Scientific Workbench can create five small, local examples from **Dashboard → Try a
synthetic example**. They are generated by the app; they contain no real
observations, private data, credentials, or network calls. The examples are
project-authored material available for testing under the project's
[PolyForm Noncommercial 1.0.0 license](../LICENSE). Their values are known
checks for a first pass, not calibrated scientific reference data.

## Before you start

Follow [INSTALL.md](../INSTALL.md) to build the app, configure the bundled
skills and a Core Python environment, and choose a dedicated output folder.
Keep that output folder separate from your inputs and from the app's example
library. These examples do not need Full, Ollama, a cloud account, or an
optional external astronomy or document program. A Core environment still
needs its documented Python packages, including Astropy, NumPy, pandas, and
pypdf where the selected capability uses them.

1. On **Dashboard**, choose **Prepare** beside an example. If your session already
   contains other inputs, confirm that they may be replaced in the selection;
   the files themselves are not altered.
2. The app makes a **new copy** under
   `~/Library/Application Support/Scientific Workbench/Examples/`, selects
   its input and suggested capability, and opens **Capabilities**. Review the
   selected input, expected result, workflow access notice, and output folder.
3. Choose **Run Capability**. The run writes to a separate new folder. Open
   **Jobs** and **Results** to inspect its status, `summary.json`,
   `manifest.json`, and any other artifacts. A process exit code alone is not
   enough to establish that the expected values were produced.
4. Return to **Dashboard** and choose **Reset Example (New Copy)** to start again.
   This creates another folder and retains every earlier copy and run. The
   generated `expected.json` records the input SHA-256 hashes and expected
   result; its `README.md` explains origin and use.

| Example | Suggested first capability | Expected first-pass check | Important limit |
| --- | --- | --- | --- |
| Small table | `profile_table` (Normal) | Three rows, four columns. | Operational values have no scientific units or interpretation. |
| FITS image | `inspect_fits` (Expert; confirm access) | One 8 × 8 primary image, 63 finite pixels, celestial reference at RA 150° / Dec −30°, one arcsecond per pixel, `adu` header unit, and a display-only PNG with WCS coordinate ticks. | The automatic preview applies only to the byte-matched generated fixture. It does not establish astrometric calibration. |
| Synthetic spectrum | `profile_table` (Normal) | Five rows, wavelength in nm and relative flux. | Profiling is not a line fit or radial-velocity measurement. |
| One-page PDF | `document_intake_workbench` (Normal) | One readable PDF page and extracted text. | Review extraction; it is not evidence of a real observation. |
| Mixed research folder | `document_intake_workbench` (Normal) | The Markdown note and PDF are inventoried. | In Results, **Inspect folder data** prepares `cross_domain_data_workbench` with the same folder for a separate reviewed run. The two jobs link through their retained input path; no combined scientific conclusion is produced. |

The generated FITS has a deterministic TAN WCS with reference pixel
`CRPIX1 = CRPIX2 = 4.5`, reference world coordinate `(150°, −30°)`, and
`CDELT1 = −1/3600`, `CDELT2 = +1/3600` degrees per pixel. It contains one NaN.
Use the [flagship workflow specification](FLAGSHIP_WORKFLOW_SPECIFICATIONS.md)
for the broader astronomy baseline and the still-pending internal GUI checks.

The automatic FITS quicklook is limited to the exact 5,760-byte synthetic input
generated by the app. Other FITS inputs keep the metadata-only guided default;
bounded-memory previews for real images are separate P2.02 work. The PNG uses a
display stretch, and a WCS header is not evidence that an image is calibrated.
Inspect `summary.json` and `manifest.json` alongside the image. For the mixed
folder, the follow-up button selects a second capability but does not execute
it automatically. Review the input and output folder before starting that job.

## Verification scope

On 2026-09-30, the four focused Swift tests passed on the maintainer's macOS
27.0.1 Mac with Swift 6.4, using the locally available macOS 26.5 SDK and the
SwiftPM native build system because the default Swift Build path failed before
compilation on that toolchain. In an **existing** Python 3.11.15 scientific
environment, all five generated examples produced `status: ok` summaries and
manifests through their actual backend commands, and all input hashes were
unchanged. A second mixed-folder table inventory also passed. Astropy
independently verified the FITS structure and reference-pixel sky coordinate
to within `1e-9` degree. On the same Mac, the maintainer used the built app to
prepare all five examples, complete six GUI jobs (the mixed folder needs two),
open a FITS result in **Results**, and reset the FITS to a second copy. Each
GUI job recorded `app_status: PASS` and `original_modified: false`; the
generated inputs still matched their `expected.json` hashes afterward. This
GUI session used the **locally installed** skill family in `~/.codex/skills`,
while the separate direct backend checks used the skills bundled in this
checkout. The evidence does not establish a fresh Core installation,
independent uncoached use, or interactive behavior on another Mac.

On 2026-10-01, the later local P0.03 implementation passed 312/312 Swift tests.
A direct run of the bundled FITS backend on the generated input returned
`status: ok`, `app_status: PASS`, an 8 × 8 image with 63 finite pixels, ICRS
TAN WCS at `(150°, −30°)`, `CUNIT1/2 = deg`, `BUNIT = adu`, and a PNG whose
WCS coordinate ticks were visually inspected. The input SHA-256 remained
`c40732799d2792ed9131899c2ad5a3b13317004a96e4d40a0d6aa959afc740de`.
The [exact-source internal GUI walkthrough](P0_03_GUI_ACCEPTANCE_2026-10-01.md)
then completed the table, FITS, and two-job mixed-folder journeys using the
bundled skills. Four accepted jobs reported `app_status: PASS` and
`original_modified: false`; all five generated input hashes matched
`expected.json` after the runs. The
[exact-candidate Core CI run](https://github.com/interemi/scientific-workbench-public/actions/runs/36996165055)
passed on macOS 15 arm64 and Intel. This meets P0.03's internal technical
criterion; unfamiliar-user success and interactive use on another Mac remain
unverified.
